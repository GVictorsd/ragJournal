# Testing

I studied how testing strategy changes as an application grows. Unit tests are useful for isolated business rules, integration tests help verify boundaries such as databases and APIs, and end-to-end tests provide confidence in important user workflows. I noticed that an excessive number of end-to-end tests can become slow and fragile. For the journal RAG application, I want to create a small evaluation set of known questions and expected source entries. That will allow me to compare retrieval changes quantitatively instead of deciding that one approach “feels better.” I also want tests for cases where no relevant information exists.
