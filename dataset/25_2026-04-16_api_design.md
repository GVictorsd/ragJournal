# API Design

I reviewed REST API design and focused on consistency rather than individual endpoint syntax. I looked at resource naming, pagination, filtering, validation errors, status codes, and versioning. One recurring problem is trying to return everything from one endpoint because it feels convenient initially. That can create large payloads and tight coupling between clients and backend models. I sketched an API for the journal application with endpoints for entries, search, tags, and retrieval results. I also considered whether the RAG answer should be returned separately from the retrieved sources. Keeping the generated answer and evidence as separate fields seems useful because the UI can then present them differently.
